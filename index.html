Model Selection
Why Random Forest?

Logistic Regression

Logistic Regression achieved higher fraud recall, identifying more of the fraudulent transactions. However, it generated 1,806 false positives , making it less practical when false alerts are costly.

Random Forest

Random Forest achieved slightly higher overall discrimination while dramatically reducing false positives to just 18 . This provided a much stronger precision/F1 trade-off for the selected operating point.

Detection Strategy
Built for imbalanced data.
◉

Class Imbalance

Only a tiny fraction of transactions are fraudulent. Accuracy alone can therefore give a misleading impression of model quality.

↗

Precision & Recall

Precision, recall, F1 and PR-AUC are used alongside ROC-AUC to evaluate performance under severe class imbalance.

◈

Probability Scoring

The Random Forest produces a fraud probability, allowing the classification threshold to be adjusted according to the desired risk tolerance.

↓

Feature Scaling

Time and Amount are transformed using the project's saved scaler before being passed to the trained model.

#

PCA Features

V1–V28 are anonymized PCA components. Their predictive importance does not directly correspond to human-readable business attributes.

◇

Configurable Threshold

The detection threshold can be adjusted to prioritize catching more fraud or reducing unnecessary alerts.

Important Context
Know the limitations.

Anonymized data means limited explainability.

The V1–V28 variables are anonymized PCA components. Therefore, feature importance can tell us which components are predictive, but it cannot directly tell us that a transaction was flagged because of a particular merchant, location, device or spending category. A production system would ideally combine model predictions with interpretable transaction attributes and explainability techniques.

Getting Started

How does FraudGuard work?

New here? Here's a quick explanation of what the scanner does and what each input means.

01

Enter transaction details

Enter the transaction amount and time. These are two of the inputs used by the machine-learning model.

02

What are V1–V28?

V1–V28 are anonymized PCA features from the credit-card fraud dataset. They represent transformed transaction information and are not directly understandable as things like merchant or location.

03

Choose a detection threshold

The threshold controls how easily a transaction is flagged. Lower thresholds catch more potential fraud but can create more false alerts.

04

Run the analysis

FraudGuard sends the transaction to the trained Random Forest model. The model returns a fraud probability and compares it with your selected threshold.

Understanding your result

Below threshold

The transaction is classified as lower risk.

Above threshold

The transaction is flagged as potential fraud.

Important: FraudGuard is an educational machine-learning project. Its predictions should not be used as the sole basis for real financial decisions.

How does FraudGuard work?

New to the project? Here's a quick guide to understanding the transaction scanner.

01 — Enter transaction details

Enter the transaction amount and time. These are two of the inputs used by the fraud detection model.

02 — V1–V28 features

V1–V28 are anonymized, PCA-transformed features from the underlying dataset. Their original meanings are not exposed.

03 — Detection threshold

The threshold determines how much predicted fraud probability is required before a transaction is flagged.

04 — Run the analysis

The trained machine-learning model evaluates the transaction and provides a fraud-risk assessment.

Note: This is an educational machine-learning project. Predictions should not be used as the sole basis for real financial decisions.
